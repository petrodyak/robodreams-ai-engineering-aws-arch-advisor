# HW 2 — RAG with sources and evals in CI: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer AWS architecture questions from a corpus of Well-Architected and Prescriptive Guidance
documents. Every claim in an answer cites a document and section. The system says "not in the documents"
when that is the case. Retrieval and answers are measured by evals that run in GitHub Actions.

**Architecture:** An offline ingest step turns PDF and HTML into `data/rag/chunks.jsonl`, using two
strategies (structure and fixed). An in-memory index built from that file serves vector, BM25, hybrid
and hybrid + rerank search with metadata filters. The answer step takes the reranked hits, keeps them
within a token budget, asks Claude Haiku 5.5 for per-claim cited JSON and validates the citations in
code. `evals/` scores retrieval and answers: deterministic scorers plus a Sonnet 5.5 judge calibrated on
Petro's labels. Answers and verdicts are cached in Git, so CI calls Claude only for cache misses.

**Tech Stack:** Python 3.12, `uv`, `pypdf`, `beautifulsoup4`, `tiktoken`, `fastembed`, `qdrant-client`,
`rank-bm25`, `anthropic`, `pydantic`, `pyyaml`, `pytest`, `ruff`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-08-hw2-rag-design.md` (approved by Petro on 09.11). Section
numbers below (§N) refer to it. Read it together with this plan.

## Review Focus

These are the inputs most likely to break for a real user that the spec does not name explicitly.
Each one has a pinned test in the task that owns the code.

1. **A Well-Architected ID in another form.** For example `rel09-bp01` or `REL09-BP01.` with
   trailing punctuation. BM25 must still rank its chunk first (Task 17.2).
2. **Filters that leave nothing.** For example `doc_types=["lens"]` together with `published_from=2030-01-01`.
   Search returns `[]`, and the answer is the not-found text with no Claude call (Tasks 17.2, 18.2).
3. **No usable text from Claude.** The answer stops with `stop_reason` `refusal` or `max_tokens`. The
   record has `found = false`, keeps the stop reason, and the run continues (Task 18.2).
4. **An oversize block.** One table or paragraph longer than 480 tokens. It is split at lines, then
   sentences, then tokens, and never emits a chunk above 480 (Task 16.3).
5. **A document with no outline or no text.** A PDF without bookmarks falls back to heading
   patterns. An HTML page with an empty article gives zero sections and is listed under
   `empty_documents` in the ingest manifest. Neither crashes the pipeline (Tasks 16.2, 16.4).
